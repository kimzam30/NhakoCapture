# NhakoCapture — todo

Reconciled against the v2.0 rebuild on 2026-08-21. Items are marked done only
where there is a test covering them; anything resting on assumption is under
**Unverified** instead.

## Done

- [x] Selection crop
- [x] Visible screen capture
- [x] Add logo to extension — `icons/`, generated by `tools/make-icons.py`
- [x] Arrow tool
- [x] Blur tool — real redaction: pixels are replaced with a blurred copy of
      themselves, so the originals are not recoverable from the export
- [x] Highlight — translucent marker under `multiply`, so text stays readable
      (this is the "rectangle highlight" idea, done as a stroke)
- [x] Pencil and text tools
- [x] Undo / redo — every mark is a record, not paint
- [x] Injecting `ShadowRoot` — the whole overlay mounts in one, with
      `all: initial` on `:host`
- [x] Improve crop math — `src/lib/geometry.js`, derived from the bitmap
      actually received rather than `devicePixelRatio`, 26 tests incl. a fuzz pass
- [x] Save button after ss, no popup for destination — now
      `downloads.download({ saveAs: true })`
- [x] Fix memory leaks — every listener registers through `cleanup.listen()`;
      three consecutive launches leave exactly one overlay in the DOM
- [x] Storage limit silently fail — the capture no longer goes through
      `chrome.storage` at all on the normal path; it is passed in the handoff
      message. The fallback editor still uses storage, but consumes and clears
      it in one shot

## Not doing

- [ ] ~~Full page screenshot via scroll-stitch~~ — **cancelled.** Opera does not
      do this; its full-page output is a PDF, and that is what shipped
      (`Save page as PDF`). The three-part stitch plan that used to live here is
      not being built.
- [ ] ~~Zoom in/out~~ — shipped as a **magnifier loupe** instead. Opera zooms its
      editor canvas; this overlay is pinned 1:1 over the live page, so scaling it
      would desync the frame from the pixels it depicts.

## Unverified

Everything below is implemented and unit-tested, but has **never run as an
installed extension in Brave**. These are the first things to check.

- [ ] Load unpacked from the repository root; confirm the toolbar icon renders
- [ ] `Ctrl+Shift+5` actually binds — Chromium rejects some `Ctrl+Shift+<digit>`
      combinations; check `brave://extensions/shortcuts`
- [ ] **Clipboard from an `http://` page.** The open question of the whole build:
      whether `navigator.clipboard.write` succeeds inside an offscreen document.
      There is a fallback that pastes as HTML — fine for chat and docs, useless
      for image editors — and the response reports which path fired
- [ ] `Save page as PDF` end to end, and that the debugger infobar clears on
      detach
- [ ] The `window.print()` fallback, by opening DevTools on the tab first
- [ ] Pixel accuracy on a real HiDPI display
- [ ] Restricted pages (`brave://settings`, the Web Store) reach the fallback
      editor window
